# Лабораторная работа 2

## 1. Постановка задачи

### 1.1. Идея и концепция

Разрабатывается программа для игры в крестики-нолики на настраиваемом поле N×N с длиной победной линии K, а также графический интерфейс для интерактивной игры против компьютера, анализа произвольных позиций и сравнения производительности различных алгоритмов поиска хода.

### 1.2. Общий класс решаемых задач

Программа решает общий класс задач принятия решений в играх с полной информацией: есть игровое состояние, множество допустимых ходов, и нужно выбрать ход, максимизирующий шансы на победу при оптимальной игре противника. Конкретные случаи (крестики-нолики, шахматы, шашки) являются частными примерами этого класса.

## 2. Сущности прикладной задачи

### 2.1. Описание сущностей

**Позиция на доске** — состояние игрового поля, определяемое расположением крестиков и ноликов на клетках поля N×N и тем, чей ход следующим. Позиция однозначно кодируется 64-битным числом для использования в таблице транспозиций.

**Ход** — действие игрока, заключающееся в установке фигуры (крестика или нолика) в свободную клетку поля. Ход характеризуется координатами клетки (строка, столбец).

**Оценка позиции** — числовая характеристика, отражающая выгодность позиции для ноликов. Вычисляется на основе количества «живых» линий (линий без фигур противника) с экспоненциальным весом.

**Таблица транспозиций** — структура данных для хранения уже просчитанных позиций, позволяющая избежать повторных вычислений при встрече с той же позицией через разные последовательности ходов.

### 2.2. Связи между сущностями

Позиция на доске содержит набор клеток, каждая из которых может быть пустой, содержать крестик или нолик. Ход изменяет позицию, добавляя фигуру в свободную клетку. Оценка позиции вычисляется на основе текущего состояния доски. Таблица транспозиций связывает позицию (ключ) с результатом её анализа (значение: оценка, глубина, тип границы).

## 3. Архитектура

### 3.1. Компоненты

**Коллекции** — абстрактный интерфейс словаря (IDictionary), его реализация на хеш-таблице с разрешением коллизий цепочками и на бинарном дереве поиска, а также динамический массив (ArraySequence) и связный список (ListSequence).

**Игровое поле (Board)** — отвечает за хранение состояния доски, проверку условий победы, генерацию возможных ходов с фильтрацией по радиусу и кодирование позиции в 64-битный ключ.

**Оценка позиции (Evaluator)** — вычисляет числовую оценку позиции с точки зрения ноликов на основе анализа живых линий.

**Поиск хода (Searcher)** — реализует алгоритмы minimax и альфа-бета отсечение для нахождения оптимального хода, использует таблицу транспозиций для ускорения работы.

**Графический интерфейс** — оболочка на SFML, отвечающая за взаимодействие с пользователем, визуализацию игрового поля и отображение результатов анализа.

### 3.2. Связи между компонентами

Графический интерфейс зависит от компонентов «Игровое поле» и «Поиск хода». «Поиск хода» читает данные из «Игрового поля» и использует словари из «Коллекций» для таблицы транспозиций. «Оценка позиции» работает с «Игровым полем» на чтение. «Игровое поле» опирается на стандартные контейнеры. «Коллекции» являются автономным нижним слоем и не зависят от других компонентов.

### 3.3. Описание компонентов

**Хранение игрового поля**: было принято решение хранить клетки в одномерном массиве с формулой индексации `row * size + col` для простоты и эффективности. Поле ограничено размером 6×6, чтобы позиция помещалась в 64-битный ключ (3^36 × 2 < 2^64).

**Алгоритм поиска**: было принято решение вынести алгоритм отдельно от игрового поля, чтобы поле отвечало только за хранение данных и проверку правил, а поиск работал с ним исключительно на чтение. Альфа-бета отсечение ускоряет перебор в 10–100 раз по сравнению с полным перебором minimax.

**Таблица транспозиций**: было принято решение использовать интерфейс IDictionary с двумя реализациями (хеш-таблица и бинарное дерево) для возможности сравнения производительности. Хеш-таблица быстрее в среднем (O(1)), но может иметь коллизии; дерево стабильнее (O(log N)), но медленнее.

**Типы границ в таблице**: было принято решение хранить тип границы (точное значение, нижняя граница, верхняя граница) вместе с оценкой позиции для корректной работы альфа-бета отсечения с таблицей транспозиций.

**Генерация ходов**: было принято решение рассматривать только ходы в радиусе от существующих фигур для ускорения перебора на больших полях, с сортировкой ходов по расстоянию до центра для улучшения эффективности альфа-бета отсечения.

**Графический интерфейс**: было принято решение сделать графический интерфейс на SFML полностью отдельным от кода игрового поля и алгоритма поиска. Поле и поиск ничего не знают об окнах, кнопках и отрисовке.

**Сообщения об ошибках**: было принято решение уведомлять вызывающий код о недопустимых операциях (выход за границы поля, попытка поставить фигуру на занятую клетку, некорректные параметры поиска) с помощью выбрасывания исключений, поскольку такие ситуации являются признаками ошибок в логике программы, а не штатными сценариями работы.

## 4. Функциональные требования

**К игровому полю:**

Хранить состояние клеток на поле N×N (от 3×3 до 6×6). Длина линии для победы K задаётся от 3 до N. Поддерживает два типа фигур: крестики и нолики.

Добавить фигуру в клетку. Если клетка занята, координаты вне поля или значение не является крестиком или ноликом, операция не выполняется и выбрасывается исключение.

Удалить фигуру из клетки (сделать клетку пустой).

Очистить поле полностью.

Проверить наличие победителя (крестики, нолики или никто). Победа определяется наличием линии длиной K из одинаковых фигур по горизонтали, вертикали или одной из двух диагоналей.

Проверить, заполнено ли поле полностью.

Получить список возможных ходов с фильтрацией по радиусу от существующих фигур. Если поле пустое, возвращается только центр. Ходы сортируются по расстоянию до центра (чебышевское расстояние), при равенстве — по строке, затем по столбцу.

Получить 64-битный ключ позиции для использования в таблице транспозиций. Ключ учитывает состояние всех клеток в троичной системе счисления и того, чей ход следующим (бит 0 или 1).

**К оценке позиции:**

Вычислить числовую оценку позиции с точки зрения ноликов. Положительная оценка выгодна ноликам, отрицательная — крестикам.

Учитывать «живые» линии (линии без фигур противника) длиной K. Оценка линии равна 10 в степени количества фигур в линии. Линии, содержащие фигуры обоих игроков, игнорируются.

**К поиску хода:**

Найти оптимальный ход для ноликов перебором на заданную глубину.

Поддерживать два алгоритма: minimax (полный перебор) и альфа-бета (с отсечением веток, где alpha >= beta).

Использовать таблицу транспозиций для запоминания просчитанных позиций. Поддерживать три режима: без таблицы, с хеш-таблицей, с бинарным деревом.

Возвращать результат с оценкой, рекомендуемым ходом, количеством перебранных позиций, количеством попаданий в таблицу и временем работы в миллисекундах.

При победе ноликов возвращать оценку WIN + remaining (чтобы компьютер стремился выиграть быстрее), при победе крестиков — -(WIN + remaining) (чтобы компьютер стремился проиграть позже).

**К словарю (IDictionary):**

Хранить пары ключ-значение. Ключ и значение могут быть любого типа.

Добавить пару (если ключ уже есть — обновить значение), получить значение по ключу (с выбрасыванием исключения при отсутствии), безопасно получить указатель на значение (nullptr при отсутствии), проверить наличие ключа, удалить пару (с выбрасыванием исключения при отсутствии), очистить словарь.

Хеш-таблица должна разрешать коллизии цепочками (списками) и автоматически изменять размер: расширяться в factor раз при заполнении, сжиматься при count <= capacity / shrinkAt.

Бинарное дерево должно поддерживать упорядоченное хранение ключей и функциональные операции Map, Where, Reduce, а также извлечение и проверку поддеревьев.

**К графическому интерфейсу:**

Отображать игровое поле с фигурами (крестики голубым, нолики зелёным).

Позволять кликать по клеткам для установки фигур. В режиме игры — только крестики, в режиме анализа — цикл пусто → X → O → пусто.

Показывать рекомендуемый ход жёлтым цветом с вопросительным знаком.

Отображать настройки: размер поля N, длина линии K, глубина перебора, радиус поиска, алгоритм, тип таблицы. Клик по кнопке настройки переключает её значение.

Предоставлять три режима: игра против компьютера (PLAY), анализ позиции (ANALYSIS), бенчмарк производительности (BENCHMARK).

В режиме бенчмарка запускать все 6 режимов (2 алгоритма × 3 вида таблицы) на пустом поле, показывать время работы столбиками в логарифмической шкале и сравнивать хеш-таблицу с деревом при вставке 2000 ключей по возрастанию, убыванию и в случайном порядке.

Сохранять результаты бенчмарка в CSV-файлы (bench_search.csv и bench_dictionary.csv).

**К системе в целом:**

Обеспечивать согласованное состояние между игровым полем и его отображением на экране при любых операциях добавления, удаления и смены режима.

Гарантировать корректную обработку любых недопустимых пользовательских действий без аварийного завершения программы.

Покрывать все основные компоненты автоматическими тестами (27 тестовых функций), включая проверку согласованности результатов всех 6 режимов поиска на случайных позициях.

Автоматически запускать тесты и проверку памяти через valgrind при каждом push в ветку master через GitHub Actions.

При смене размера поля автоматически устанавливать безопасное значение глубины перебора, чтобы избежать чрезмерно долгого счёта.
